## Decisions I made on your behalf (details in bd memories)

1. Migrations are generated by one bead at a time; parallel drizzle-kit runs collide on the journal.
2. Secrets store is file-based under `<dataDir>/secrets`, not a table. Platform settings reuse the `platform_meta` table.
3. Password auth: scrypt, cookie `cm_session`, `Secure` off by default (Tailscale over http), absolute 30 day expiry, admin password via `CM_ADMIN_PASSWORD`, rate limiting added (10.9).
4. Trusted-header strategy: the web proxy does not strip the header; safety rests on the fronting proxy overwriting it. `/info` requires auth; `/auth/strategy` is public.
5. PWA uses a hand-written no-cache service worker so the app cannot look alive when the daemon is down.
6. Codex sessions default to the adapter's `read-only` mode; `workspace-write` is the only other allowed mode; auto-review modes are refused.
7. The claude-acp wire key `DECISION_META_KEY` stays `clanker-corner` so protocol behaviour is unchanged.
8. Plugin management, grants, bots and project modules are admin-only. Activity and registry reads are open to any signed-in actor.
9. Repository type uses GitHub GraphQL for branch dates (REST elsewhere); `defaultBranch` is an optional override.
10. Routes: project pages at `/p/<slug>/<capability>`; layers at `apps/web/layers/<capability-id>/`, enforced by the `cm-layers` lint plugin.
