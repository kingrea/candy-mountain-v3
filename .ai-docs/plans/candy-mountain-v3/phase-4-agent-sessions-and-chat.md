# Phase 4: Agent sessions and chat panel

**Capability:** Claude Code and Codex are configured per project, and I can chat with either from a panel on any page, with permission prompts answered in the UI and transcripts that survive reloads and daemon restarts.

## What and why

**ACP harness.** The daemon speaks ACP to both agents using the ACP SDK directly, not through Mastra's ACP wrapper (both Clanker and v2 had to patch it and it drops events). Lift Clanker's Claude shim as a workspace package: it drives the stock `claude` binary with the stdio permission protocol, resumes by session id, relays permission prompts and questions, and strips every API-key and gateway variable from the child environment so billing stays on the configured login. Codex runs through the official Codex ACP adapter with the browser disabled and its default auto-review mode rejected, as Clanker does. Each session gets a curated environment and a working directory; in this phase the working directory is the project's checkout, since worktrees arrive with bots in Phase 6.

**Claude Code plugin and Codex plugin.** Both are per-project plugin types. Each owns a private config home for that project so different projects can use different accounts. Configuring the plugin means logging the CLI in: the daemon starts the CLI's login flow in that home, shows the URL (and for Codex the one-time code) in the plugin page, accepts the pasted code for Claude Code, and confirms with the CLI's own status command. Health is "logged in". Revoking deletes the home. v2's pasted long-lived token remains an alternative for Claude Code. The plugin pages must handle the refresh-lock quirk Clanker hit: do not probe login status right before starting a session.

**Session lifecycle.** A session belongs to a project, an agent family, and an actor, and records its upstream session id so it can be resumed after a daemon restart. Every event the agent emits is appended to a durable per-session event log, which is what the browser streams over SSE and what it replays after a reload (the v2 transcript loss was the main reason harness chat felt unfinished). Idle sessions are reaped after a timeout; a concurrency cap keeps the machine usable. Permission requests and agent questions become pending decisions that the UI answers; decisions are chosen by option kind never by position, unexpected ones are refused, and an unanswered decision times out to refusal. A never-bypass rule applies: no configuration may put either agent into a bypass-permissions mode.

**Chat layer.** A shared chat layer, not a capability, mounted on every page: a rail listing agents the registry says the actor may chat with for the selected project, a panel with threads, a transcript, and a prompt bar; unread and working indicators; deep links to a thread. Threads are per actor and per project. Two agents appear in this phase, "Claude Code" and "Codex", each present only when its plugin is healthy for the project. The transcript renders text, reasoning, tool calls with their results, usage, and permission cards with Allow once, Always allow (only rules the agent itself proposed), and Deny. Model and effort are selectable where the agent supports it, and changing them starts a fresh session. The chat layer is designed so Phase 6 can add bot agents and Phase 10 a native platform agent without changing it.

**Where this sits in the registry.** Chatting with Claude Code and Codex are capabilities in the Agent Hub module, each requiring its plugin. The Agent Hub module must therefore be enabled for a project before the agents appear.

## Human test

For one project, configure Claude Code through the plugin page by completing the login in a browser and pasting the code, and configure Codex with the device flow. Enable Agent Hub. Open the chat rail, start a Claude Code thread, ask it to list the repo's top-level directories, and watch the tool call stream. Ask it to create a scratch file and confirm a permission card appears; deny it and confirm nothing was written; allow a second attempt. Reload the page mid-turn and confirm the transcript is intact and the turn finishes. Restart the daemon, send another message in the same thread, and confirm the agent still has its context. Repeat the first exchange with Codex. Confirm a project without the plugins shows neither agent.
